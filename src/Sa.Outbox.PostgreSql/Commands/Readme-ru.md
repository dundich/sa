# Команды

## Обзор

Эта папка содержит команды работы с данными, которые преобразуют высокоуровневые операции outbox в конкретные PostgreSQL-запросы. Каждая команда владеет собственным `SqlCacheSplitter` для прозрачной батчинговой обработки.

| Файл | Назначение |
|---|---|
| `BulkInsertMsgCommand.cs` | Массовая вставка сообщений в таблицу outbox через BINARY COPY |
| `FinishDeliveryCommand.cs` | Помечает доставленные сообщения как завершённые (OK / Accepted / NoContent) |
| `ErrorDeliveryCommand.cs` | Фиксирует перманентные ошибки неудачных доставок |
| `ExtendDeliveryCommand.cs` | Продлевает TTL блокировки активных записей доставки |
| `StartDeliveryCommand.cs` | Создаёт начальные записи задач в очереди задач |
| `SelectTenantCommand.cs` | Выбирает активные идентификаторы тенантов |
| `SelectMsgTypeCommand.cs` | Выбирает зарегистрированные типы сообщений из реестра |
| `InsertMsgTypeCommand.cs` | Вставляет новые регистрации типов сообщений |
| `NpgsqlOutboxReader.cs` | Низкоуровневые вспомогательные методы чтения таблиц outbox |
| `NpgsqlCommandExtension.cs` | Расширения для добавления типизированных параметров в `NpgsqlCommand` |
| `Setup.cs` | DI-хелперы для регистрации команд |

## SqlCacheSplitter

Основная логика разделения батчей находится в `SqlCacheSplitter.cs`. Подробности — в XML-документации класса.

### Зачем он нужен

PostgreSQL имеет жёсткое ограничение — **65 535 параметров** на одно выражение. При обработке сотен или тысяч сообщений outbox в одном батче сгенерированный SQL легко превысит этот лимит. Сплиттер:

1. Нарезает батч на чанки, укладывающиеся в безопасный бюджет — до `DefaultMaxLen` (1024) элементов, исходя из замеренных **8 (+4 переиспользуемых общих)** параметров на строку в `SqlFinishDelivery` и 4 в `SqlError`: 1024-строчный finish-чанк связывает 8196 параметров = 12.5% лимита. Прежняя оценка «~16 параметров на элемент» была завышена в 2–4 раза (замер: `SqlOutboxBuilderTests.BulkStatements_ParameterPerRowRatio_Is8And4_Not16`).
2. Выравнивает границы чанков до кратных 16, чтобы размеры чанков оставались внутри преаллоцированного кеша имён параметров.
3. Кэширует сгенерированные SQL-шаблоны по длине, чтобы одинаковые размеры reused ту же строку.

Кэш ограничен максимум **79 записями** (кратные 16 до 1024 + остатки 1–15). В худшем случае — при генерации каждого ключа — это несколько МБ SQL-текста; реальный потребитель использует лишь 2–4 разных размера, поэтому на практике это несколько строк — никогда не бесконечно.

### Как его используют

```csharp
foreach ((string sql, int length) in _sqlCache.GetSql(messages.Length))
{
    var slice = messages.Slice(startIndex, length);
    startIndex += length;
    // выполнить sql с slice сообщений
}
```

Каждая итерация выдаёт один SQL-шаблон и сколько элементов он покрывает. Caller нарезает входную коллекцию соответственно и выполняет команду.
