# Type Resolve — Sa.Outbox.PostgreSql

## Назначение

Модуль **Type Resolve** предоставляет лёгкий механизм с учётом кэширования для маппинга между полными именами типов и компактными целочисленными кодами (`long`) в системе outbox.

В архитектуре outbox каждый тип сообщения (например, `"OrderCreated"`, `"EmailSent"`) хранится в таблице `__type$` как пара `(long id, string typeName)`. Вместо хранения полного имени типа в каждой записи сообщения, система хранит только числовой код — это уменьшает объём хранимых данных и улучшает производительность JOIN-ов на партиционированных таблицах.

## Компоненты

| Класс / Интерфейс | Роль |
|---|---|
| `IOutboxTypeCache` | Слой кэша поверх таблицы `__type$`. Загружает все маппинги типов в память по требованию. |
| `OutboxTypeCache` | Конкретная реализация. Содержит двунаправленные словари (`long → string` и `string → long`), обновляемые лениво через `ResetLazy`. |
| `IOutboxTypeResolver` | Резолвер высокого уровня, координирующий попадания в кэш, вставки в БД и вычисление хеша. |
| `OutboxTypeResolver` | Оркестратор: проверка кэша → вычисление MurmurHash3 при промахе → вставка в БД → обновление кэша. Потокобезопасен через `Interlocked`. |
| `Setup.AddOutboxTypeResolver()` | Расширение DI, регистрирующее оба сервиса как синглтоны. Вызывается автоматически при регистрации `Sa.Outbox.PostgreSql`. |

## Как это работает

1. **Поиск по имени** (`GetHashCode(typeName)`):
   - Проверка в памяти → если найдено, вернуть код.
   - Если не найдено, вычислить `MurmurHash3` от имени типа → использовать как код.
   - Вставить `(code, typeName)` в таблицу `__type$` (один раз на процесс, защищено `Interlocked.CompareExchange`).
   - Сбросить кэш, чтобы последующие запросы попали в память.
   - Вернуть код.

2. **Поиск по коду** (`GetTypeName(code)`):
   - Проверка в памяти → если найдено, вернуть имя.
   - Если не найдено, сбросить кэш (предполагается устаревшие данные) и повторить.
   - Если всё ещё отсутствует, вернуть `code.ToString()` как безопасный запасной вариант.

## Зачем MurmurHash3?

Использование детерминированного хеша как кода типа обеспечивает:
- **Компактное хранение**: 8 байт вместо строк переменной длины.
- **Детерминированность**: одно и то же имя типа всегда даёт одинаковый код во всех процессах.
- **Достаточную устойчивость к коллизиям** для контекста outbox.
- **Отсутствие зависимости от автоинкремента**: избегает гонок при одновременной регистрации типов несколькими воркерами.

## Потокобезопасность

- Флаг `_triggered` использует `Interlocked.CompareExchange`, чтобы гарантировать выполнение вставки в БД + сброса кэша только одним потоком при каждом промахе.
- Кэш загружается лениво через `ResetLazy<Task<Storage>>`, что предотвращает «шторм» запросов при конкурентном чтении.

## Регистрация в DI

```csharp
services.AddOutboxTypeResolver(); // регистрируется внутренне
// Разрешается в:
// IOutboxTypeCache     → OutboxTypeCache     (синглтон)
// IOutboxTypeResolver  → OutboxTypeResolver  (синглтон)
```
