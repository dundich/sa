## Обзор

В этой папке находятся типы, отвечающие за генерацию и параметризацию всех SQL-запросов, используемых подсистемой исключающего почтового ящика (outbox) на базе PostgreSQL. В отличие от папки `Commands` (которая преобразует высокоуровневые операции в конкретные `NpgsqlCommand`-вызовы), `SqlBuilder` владеет **самими SQL-шаблонами** и инфраструктурой, обеспечивающей их работу при высоких нагрузках.

## Структура файлов

| Файл | Назначение |
|---|---|
| `SqlOutboxBuilder.cs` | Основной класс, содержащий все строки SQL-шаблонов, а также вспомогательные методы для динамической генерации списков значений (вставка ошибок, завершение доставки); размер `StringBuilder` берётся из числа строк. |
| `SqlParam.cs` | Статический класс с именованными константами для каждого заполнителя SQL-параметра (например, `@tnt`, `@gr`, `@frm`). Обеспечивает консистентность во всех запросах. |
| `Setup.cs` | Метод расширения DI (`AddOutboxSqlBuilder`), регистрирующий keyed `SqlOutboxBuilder` на каждый ключ провайдера. |

## Шаблоны

Все шаблоны строятся при конструировании с использованием имён таблиц/столбцов из `PgOutboxTableSettings`, поэтому результирующий SQL адаптируется под конкретную схему БД потребителя.

### Статические шаблоны (константные строки)

| Поле | Описание |
|---|---|
| `SqlBulkMsgCopy` | Двоичный COPY-IN для массового вставки сообщений из STDIN |
| `SqlCreateTypeTable` | Создаёт таблицу справочника типов, если отсутствует |
| `SqlSelectType` | Выбор всех строк из таблицы типов |
| `SqlInsertType` | Вставляет новую запись типа с `ON CONFLICT DO NOTHING` |
| `SqlCreateOffsetTable` | Создаёт таблицу отслеживания смещений, если отсутствует — содержит и легаси `group_offset` (UUID v7, остаётся для раскатки без даунтайма, удаляется отдельной версией-контрактом), и живой `group_offset_seq` (курсор BIGINT по `msg_seq`) |
| `SqlSelectOffset` / `SqlUpdateOffset` / `SqlInitOffset` | Чтение, продвижение и ленивое создание смещения группы потребителей. Все три работают с `group_offset_seq` — легаси-UUID-колонку эта версия не читает. Создание смещения — это `INSERT ... ON CONFLICT DO NOTHING`, поэтому `SqlInitOffset` покрывает и вставку, и пустую операцию. Отдельный `SqlInsertOffset` когда-то существовал и удалён как мёртвый код (заодно он был синтаксически битым: лишняя вторая `;`, которую Npgsql отверг бы как `42601`) |
| `SqlLockOffset` | Advisory-замок (`pg_advisory_xact_lock`) для сериализации записи смещений |
| `SqlLockAndSelect` | Запрос с CTE: выбирает ожидающие/восстановимые задачи, помечает их как `Processing`, присоединяет таблицу сообщений и возвращает полезную нагрузку. Использует `FOR UPDATE SKIP LOCKED` для безопасного конкурентного потребления |
| `SqlExtendDelivery` | Продлевает TTL блокировки для текущей обрабатываемой задачи |
| `SqlLoadConsumerGroup` | Массово вставляет задачи из таблицы сообщений в очередь задач, возвращая количество скопированных строк и максимум `msg_seq` среди вставленных — новый курсор потребления (C2). `ORDER BY`/`WHERE`/`RETURNING` живут на `msg_seq`, никогда на v7-идентификаторе |
| `SqlResolveMsgIdFloor` / `SqlResolveDateFloor` | Трансляция легаси-флоров (C2): превращают `WithMinOffset`-флор (v7-id или дата) в эксклюзивную границу `msg_seq` — `MAX(msg_seq)` сообщений, которые всё ещё сортируются ниже флора, либо 0, если таких нет. Кэшируется лоадером на группу |
| `SqlAddMsgSeqColumnToMsgTable` / `SqlAddMsgSeqColumnToTaskTable` / `SqlAddGroupOffsetSeqColumnToOffsetTable` | Идемпотентные апгрейд-хуки в стиле C14 (`ADD COLUMN IF NOT EXISTS`, выполняются в post-хуке Partitional на каждом проходе миграции): приводят схему существующего деплоя к C2-форме. Меняют только схему — бэкфилл значений курсора на наполненной БД остаётся ручным шагом (документирован) |

### Динамические шаблоны (генерируются при вызове)

| Метод | Описание |
|---|---|
| `SqlError(int count)` | Генерирует многострочные INSERT-запросы для записей об ошибках (параметризуется по количеству) |
| `SqlFinishDelivery(int count)` | Завершает пакет доставки: вставляет лог-записи, затем обновляет соответствующие записи задач |

Оба динамических метода создают `StringBuilder` нужного размера (пула нет: аренда и возврат оказались дороже `new` для таких объёмов).

## Регистрация в DI

Метод `Setup.AddOutboxSqlBuilder` регистрирует одну вещь на ключ провайдера:

- keyed-синглтон `SqlOutboxBuilder`, собранный из `PgOutboxTableSettings` этого ключа (ключ — ключ
  скопа outbox, поэтому два провайдера сохраняют свои имена таблиц и шаблоны).

Регистрации `ObjectPool` нет: динамические билдеры создают обычный `StringBuilder` нужного размера по
числу строк (`count * 48` / `count * 96`) — по замерам это дешевле аренды/возврата в пул для таких
объёмов.

## Примечания к дизайну

- **StringBuilder нужного размера** — Многострочные списки значений (ошибки, доставки) создают `StringBuilder` с размером по числу строк, а не берут его из пула.
- **Advisory-замки** — Запись смещений сериализуется через `pg_advisory_xact_lock`, что предотвращает состояния гон без тяжёлых табличных блокировок.
- **Курсор на `msg_seq`, а не на v7-идентификаторе (C2)** — `msg_id` чеканится часами приложения, поэтому скошенные или откаченные часы могут заставить новое сообщение сортироваться *ниже* уже продвинутого курсора, и `msg_id > @offset` пропустит его навсегда. `msg_seq` (BIGSERIAL) назначается базой в момент COPY, поэтому «строка новее» и «seq больше» — одно и то же по построению, и курсор не может обогнать ещё не вставленную строку. Легаси-UUID `group_offset` остаётся в offset-таблице для бесшовной раскатки и удаляется отдельной версией-контрактом.
- **SKIP LOCKED** — Выбор задач использует `FOR UPDATE SKIP LOCKED` PostgreSQL, позволяя нескольким потребителям безопасно конкурировать за работу.
- **ON CONFLICT DO NOTHING** — Идемпотентные вставки защищают от повторной обработки при повторах.
- **Шаблонизация схемы** — Каждый шаблон разрешает имена таблиц/столбцов из `PgOutboxTableSettings` при конструировании, поэтому рантайм-конкатенация строк не требуется.
