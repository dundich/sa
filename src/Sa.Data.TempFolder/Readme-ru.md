# Sa.Data.TempFolder

Управление временными каталогами: подпапки под корнем с защитой от выхода за пределы, отложенная фиксация активности записью, фоновая очистка по возрасту, сканирование объёма на пониженном приоритете с edge-событием о превышении лимита и опциональный контроль свободного места. Совместимо с Native AOT, мультиинстансальная регистрация по ключу.

## Обзор

`AddSaTempFolder` регистрирует один (или несколько) инстансов `ITempFolder` с ключом — корневой каталог плюс стратегии и политики, настроенные для него:

- **Защита путей** — каждый аргумент пути проходит через `PathGuard`: он может быть относительным или абсолютным, но результат обязан остаться внутри корня; `..`-сегменты и инъекционные символы (`~`, `>`, shell-метасимволы, управляющие/невидимые Unicode) отклоняются (`SecurityException`).
- **Очистка по возрасту** — просроченная папка верхнего уровня удаляется целиком; свежая — обходится рекурсивно, и то же правило применяется на каждом вложенном уровне, поэтому датовые иерархии (`yyyy/MM/dd/HH` …) теряют старые дни/часы, пока живы контейнеры года/месяца (фильтр по префиксу — на верхнем уровне, лимит на проход, от старших к младшим, `Retry.Linear` на временных ошибках I/O). Файлы прямо в корне никогда не трогаются.
- **Датовое именование** — `Naming = Date` называет папки `{FolderPrefix}+{текущее время в форме FolderNameFormat}` (любой из `yyyy-MM-dd`, `yyyy-MM-dd/HH`, `yyyy/MM/dd`, `yyyy/MM/dd/HH`, `yyyyMMdd`, `yyyyMMdd/HH`, `yyyyMM/dd`, `yyyyMM/dd/HH` …) — читаемая иерархия, которую очистка может старить поуровнево. `GuidV7` остаётся значением по умолчанию.
- **Отложенная фиксация активности** — серия записей перевзводит один таймер на затронутую папку; только тишина длиной `TouchDebounce` реально обновляет время записи собственной папки записанного файла **и всех его предков до корня**, поэтому активные иерархии переживают очистку на каждом уровне.
- **Очистка уступает записям** — идущие `SaveStreamAsync` / `CopyFileAsync` / `CreateSubfolder` отменяют проход очистки: проход не стартует, пока идёт запись (возвращает 0), а запущенный в момент записи завершается отменой на следующем чекпоинте; папка с ещё не приземлившимся debounce-касанием пропускается — только что записанный файл никогда не удаляется.
- **Политика перезаписи** — `SaveStreamAsync` / `CopyFileAsync` по умолчанию заменяют существующий файл; `OverwriteFiles = false` заставляет запись упасть с `IOException` (оригинал остаётся нетронутым).
- **Учёт объёма** — опциональное фоновое сканирование на пониженном приоритете (`ThreadPriority.BelowNormal`) измеряет весь корень, кэширует размеры по папкам (ключ — время записи папки) и вызывает `OnVolumeExceeded` **edge-триггером** (один раз при входе в превышение и один раз при возврате в норму). Событие только уведомляет — из-за объёма ничего не удаляется.
- **Контроль свободного места** — по умолчанию выключен; при `MinFreeSpace > 0` сервис опрашивает свободное место на томе корня (первый замер при старте хоста, далее — раз в `FreeSpaceCheckInterval`, по умолчанию 24 ч) и вызывает `OnFreeSpaceReached` **edge-триггером**, когда замер достигает лимита.
- **Fail-fast на старте** — фоновый сервис проверяет доступ ко всем корням (создание / листинг / пробная запись) до запуска циклов.

## Быстрый старт

```csharp
using Sa.Data.TempFolder;

builder.Services.AddSaTempFolder("uploads", b => b.Options(ob => ob.Configure(options =>
{
    options.RootPath = "/var/tmp/uploads";
    options.MaxAge = TimeSpan.FromHours(6);
    options.FolderPrefix = "up_";
})));
```

Получение — по ключу (обычный `GetRequiredService<ITempFolder>()` ключевые сервисы **не** находит):

```csharp
var temp = sp.GetRequiredKeyedService<ITempFolder>("uploads");

var jobDir = temp.CreateSubfolder("jobs/42");
var (relative, absolute) = await temp.SaveStreamAsync(stream, "jobs/42/payload.bin", ct);
await foreach (var file in temp.EnumerateFilesAsync("*.part", "jobs", recursive: true, ct)) { … }
var removed = await temp.CleanupAsync(ct);
```

Колбэк `configure` получает `ITempFolderBuilder`: секция задаётся через `FromConfiguration("…")`, а стандартные `Configure` / `PostConfigure` / `Validate` — через `Options(...)`; отдельной перегрузки с опциями нет.

### Из конфигурации

```json
{
  "TempFolder": {
    "RootPath": "/var/tmp/uploads",
    "MaxAge": "06:00:00",
    "FolderPrefix": "up_",
    "CleanupInterval": "01:00:00",
    "TrackVolume": true,
    "MaxTotalSize": 10737418240
  }
}
```

```csharp
builder.Services.AddSaTempFolder("uploads", b => b.FromConfiguration("TempFolder"));
```

Скалярные значения биндятся из секции; `OnVolumeExceeded` и `OnFreeSpaceReached` — код-каналы, конфигурация их никогда не создаёт. Секция биндится первым шагом, поэтому `Configure` внутри `Options(...)` всегда перекрывает конфигурацию.

### Несколько инстансов

```csharp
builder.Services.AddSaTempFolder("uploads", b => b.FromConfiguration("TempFolder:Uploads"));
builder.Services.AddSaTempFolder("exports", b => b.Options(ob => ob.Configure(o => o.MaxAge = TimeSpan.FromMinutes(30))));

var uploads = sp.GetRequiredKeyedService<ITempFolder>("uploads");
var exports = sp.GetRequiredKeyedService<ITempFolder>("exports");
```

Каждый вызов получает собственный именованный экземпляр опций (секции и `Configure`-колбэки не накапливаются между регистрациями). Повторное использование имени падает с ошибкой сразу при регистрации.

### Переопределения из кода

```csharp
builder.Services.AddSaTempFolder("special", b => b
    .UseCleanupStrategy<EverythingExpiredStrategy>()  // перекрывает enum Cleanup
    .UseNamingStrategy<JobFolderNameStrategy>());     // перекрывает enum Naming
```

Переопределённый тип регистрируется как синглтон (его зависимости резолвятся из контейнера) и привязывается к ключевому слоту стратегий этого инстанса. Встроенные выбираются по enum-ам `Cleanup` / `Naming`: по умолчанию `AgeBased` + `GuidV7`, либо `AgeBased` + `Date` (с `FolderNameFormat`), если настроено:

```csharp
builder.Services.AddSaTempFolder("byday", b => b.Options(ob => ob.Configure(o =>
{
    o.Naming = TempFolderNamingKind.Date;      // папки вида "up_2026/10/08/14"
    o.FolderNameFormat = "yyyy/MM/dd/HH";      // любой формат даты/времени .NET
    o.FolderPrefix = "up_";                    // ложится на первый сегмент
})));
```

Формат рендерится инвариантной культурой по времени контейнера (`TimeProvider`, локальное время), а его форма проверяется вместе с префиксом — сломанный или инъекционный формат валит `OptionsValidationException` при резолве/старте.

## API

| Метод | Описание |
|---|---|
| `Name` / `RootPath` | Ключ регистрации и полностью квалифицированный корень. |
| `CreateSubfolder(rel?)` | Создаёт подпапку (включая родительские) — `rel` относительный или абсолютный (внутри корня). Без аргумента имя даёт стратегия именования: `GuidV7` → `{FolderPrefix}{guid-v7:N}` (сортируется по времени, не конфликтует); `Date` → `{FolderPrefix}{FolderNameFormat}` (вызовы в одном временном сегменте делят одну папку). |
| `SaveStreamAsync(stream, relPath, ct)` | Пишет поток в файл — `relPath` относительный или абсолютный (внутри корня) — создавая родителей, и (с debounce) активирует цепочку затронутых папок. Перезаписывает существующий файл, если только `OverwriteFiles = false`. Возвращает `(RelativePath, AbsolutePath)`. |
| `CopyFileAsync(src, relDir?, ct)` | Копирует внешний файл внутрь — `relDir` относительный или абсолютный (внутри корня); без подпапки стратегия строит новую, файл сохраняет своё имя (само имя тоже должно проходить [правила путей](#правила-путей)). Политика перезаписи — как у `SaveStreamAsync`. |
| `EnumerateFilesAsync(pattern, relDir?, recursive?, ct)` | Асинхронно перечисляет подходящие файлы, возвращает абсолютные пути. `relDir` относительный или абсолютный (внутри корня); `pattern` — это шаблон, а не путь, поэтому `*`/`?` там разрешены. |
| `CleanupAsync(ct)` | Один проход очистки; возвращает число удалённых папок (для read-only — всегда 0). Уступает записям: отменён (0), пока запись идёт, прерван, если запись началась посреди прохода, папки с неприземлившимся касанием активности пропускаются. |
| `CheckAccessAsync(ct)` | Проверяет корень: создаёт при отсутствии (только на запись), листает, выполняет пробную запись/создание/удаление. |

## Правила путей

Каждый аргумент пути (`rel`, `relPath`, `relDir`) до обращения к файловой системе проходит через `PathGuard`:

- **Относительный или абсолютный — принимаются оба.** Абсолютный путь используется как есть, но обязан разрешаться в сам корень или в место внутри него, иначе `SecurityException`. Никакого раскрытия нет: `~/…` отклоняется, а не переписывается в домашний каталог.
- **`..` отклоняется как сегмент на любом из разделителей, где угодно** — даже `jobs/../jobs/42`, который нормализуется в путь внутри корня. Такое в temp-путях никому не нужно.
- **Инъекционные символы отклоняются** с `SecurityException` до любой нормализации:
  - управляющие ASCII-символы `0x00–0x1F` / `0x7F` (обрезка по NUL, `\t`, `\r`, `\n` …);
  - shell/glob-метасимволы `` ~ < > | & ; ` $ ^ * ? " ' % `` — редиректы, пайпы, цепочки/подстановка команд, переменные и переменные окружения, нарушение кавычек, глобbing и percent-кодирование обхода (`..%2f`);
  - литеральный `\` на Unix (Windows-путь или shell-эскейп, протащенный в Unix-путь);
  - Unicode-символы формата — невидимые пробелы, bidi-перевороты (U+202E) и подобные;
  - на Windows: двоеточие вне спецификации диска `C:` (альтернатовые потоки NTFS).
- **Нормализация всё равно выполняется после**: `Path.GetFullPath` + проверка вложенности с учётом разделителей, поэтому сосед с общим префиксом имени корня (`/var/tmp/uploads_evil` при корне `/var/tmp/uploads`) никогда не считается потомком.
- `FolderPrefix` подчиняется тем же правилам (валидация при резолве/старте хоста — `OptionsValidationException`). `pattern` перечисления исключён: `*`/`?` принадлежат шаблонам.

## Очистка

Один проход = выборка стратегией → защищённое удаление:

1. Стратегия (`AgeBased` по умолчанию) отбирает подпапки с возрастом больше `MaxAge`, от старших к младшим по всем уровням, не больше `MaxFoldersPerPass` за проход. Возраст берётся из `AgeSource`: `LastWriteTime` (по умолчанию — обновляется debounce-ом при записях) или `CreationTime`.
2. **Правило спуска:** просроченная папка **верхнего уровня** (с фильтром по `FolderPrefix`) удаляется целиком со всем содержимым; свежая папка верхнего уровня — обходится вглубь, и то же правило рекурсивно применяется на каждом внутреннем уровне. Именно так работают датовые иерархии — `2026` живёт год, а его старые месяцы внутри вычищаются, и просроченный месяц уносит свои дни, не требуя отдельного обхода. Фильтр по префиксу действует только на папках верхнего уровня (вложенные папки — собственная структура инстанса: повторный фильтр по префиксу освободил бы от очистки каждый внутренний уровень); папка верхнего уровня без префикса пропускается **и не обходится**. Спуск останавливается на глубине 16 и пропускает папки, исчезнувшие или ставшие нечитаемыми посреди прохода.
3. Инстанс заново валидирует каждый возвращённый путь относительно корня (враждебная стратегия не выйдет за пределы), удаляет через `Retry.Linear` (3 попытки, только временные `IOException` / `UnauthorizedAccessException`) и считает результат.
4. **Проход уступает файловой активности.** Идущие `SaveStreamAsync` / `CopyFileAsync` / `CreateSubfolder` (или незавершённое касание маркеров) отменяют проход целиком — он возвращает 0, а следующий интервал повторяет попытку. Запись, пришедшая посреди прохода, вместо этого отменяет токен прохода: удаление завершается отменой на своём следующем чекпоинте, а запись продолжается, как только проход разворачивается. Папка с ещё не приземлившимся касанием пропускается явно — файл, записанный минуту назад, никогда не уходит вместе со своей папкой.

Удалено → `LogInformation`; папка не удалилась после попыток → `LogWarning`, проход продолжается. Файлы прямо в корне — вне области очистки.

## Отложенная фиксация активности

При `AgeSource=LastWriteTime` активно записываемая папка не должна выглядеть просроченной — на **любом** уровне иерархии. После каждой записи взводится один таймер на затронутую папку (собственную директорию записанного файла): новые записи в течение `TouchDebounce` (по умолчанию 5 с) перезапускают его, и только тишина этой длины выставляет `LastWriteTimeUtc` = «сейчас» — этой директории **и всем её предкам до (исключая) корень**, по одному уровню за раз. Цепочка нужна, потому что сами по себе перезаписи не двигают mtime директории, а вложенная очистка считает возраст и промежуточных уровней: файл в `up_2026/10/08/14/f.bin` освежает `14`, `08`, `10` и `up_2026`. Сам корень инстанса никогда не трогается. Незавершённые касания отбрасываются при Dispose (папки просто остаются старее — безопасное направление). Сам обход идёт под тем же исключением, что и записи — проход очистки никогда его не пересекает, — и запись о незавершённом касании снимается только после того, как обход приземлился; именно это позволяет очистке отличать «только что записано, пощади» (пропуск) от «давно тихо, бери» (удаление).

## Учёт объёма

По умолчанию выключен: при `TrackVolume=false` объём никогда не вычисляется, `MaxTotalSize` инертен. При включённом (и `MaxTotalSize > 0`):

- Измерение идёт на выделенном фоновом потоке с `ThreadPriority.BelowNormal` — обход большого дерева не вытесняет рабочие потоки.
- Размеры по папкам кэшируются по времени записи папки; заново обходятся только изменённые или затронутые папки.
- Скан выполняется **перед каждым проходом очистки**, плюс по своему интервалу, если `VolumeScanInterval > 0` (по умолчанию `0` — только перед очисткой).
- `OnVolumeExceeded` срабатывает edge-триггером: один раз при пересечении `MaxTotalSize` вверх и один раз при возврате в норму — без повторов, пока состояние не меняется. Переход дополнительно логируется (`Warning` / `Information`). Исключения обработчика перехватываются и логируются. **Из-за объёма ничего не удаляется** — очистка остаётся возрастной; событие предназначено подписчику (метрики, действие администратора, адаптивный троттлинг).

```csharp
options.OnVolumeExceeded = e =>
    metrics.TempExceeded(e.Name, e.TotalSize, e.MaxTotalSize, e.Exceeded);
```

## Свободное место

По умолчанию выключен: при `MinFreeSpace = 0` (по умолчанию) том никогда не опрашивается. Когда задан лимит, фоновый сервис выполняет по одному замеру на инстанс:

- **Замер — одна stat-операция по тому** (`DriveInfo` по тому корня; на Unix — сам путь корня, чтобы попасть именно в его маунт, на Windows — корень диска). Без обхода дерева и без отдельного потока; сбой замера (том пропал, нет прав) логируется циклом и повторяется на следующем интервале.
- **Расписание** — `FreeSpaceCheckInterval` (по умолчанию 24 ч): первый замер выполняется сразу при старте хоста — уже тесному тому нужно проявиться немедленно, а не через сутки, — далее — раз в интервал.
- `OnFreeSpaceReached` работает edge-триггером, как и `OnVolumeExceeded`: один раз, когда замер падает до `MinFreeSpace` включительно (`Reached = true`), и один раз, когда поднимается выше (`Reached = false`) — без повторов, пока состояние не меняется, поэтому суточный опрос не заливает подписчика шумом. Первый замер **выше** лимита молчит (до сих пор ничего не достигнуто), а первый замер **уже на** лимите срабатывает сразу. Переходы логируются (`Warning` / `Information`); исключения обработчика перехватываются и логируются. **Из-за свободного места ничего не удаляется** — событие предназначено подписчику (метрики, алерты, выгрузка папки).

```csharp
builder.Services.AddSaTempFolder("uploads", b => b.Options(ob => ob.Configure(o =>
{
    o.MinFreeSpace = 5L * 1024 * 1024 * 1024; // 5 ГиБ
    o.OnFreeSpaceReached = e =>
        alerts.TempFreeSpace(e.Name, e.AvailableFreeSpace, e.MinFreeSpace, e.Reached);
})));
```

## Фоновый сервис

Один `TempFolderCleanerHost` на коллекцию сервисов обходит **все** регистрации:

- **На старте** — `CheckAccessAsync` для каждого инстанса; неработающий корень валит старт хоста с понятным сообщением, а не всплывает при первом использовании.
- **Затем** — свой цикл очистки на инстанс (`CleanupInterval`, первый проход через интервал) и, при настройке, цикл сканирования объёма (`VolumeScanInterval`, первый проход сразу) и цикл проверки свободного места (`FreeSpaceCheckInterval`, первый проход сразу). Сбои прохода логируются и не роняют хост; все задержки идут через `TimeProvider` контейнера, поэтому тесты виртуализируют расписание.

## Режим read-only

`ReadOnly=true` переводит инстанс в режим чтения:

- `CreateSubfolder` / `SaveStreamAsync` / `CopyFileAsync` бросают `InvalidOperationException`.
- `CleanupAsync` возвращает `0`, а фоновый сервис **полностью игнорирует** инстанс — ни очистки, ни сканирования объёма, ни события, ни проверки свободного места.
- Проверка на старте тогда проверяет только наличие корня и возможность его листать (создания не происходит).

## Справочник опций

| Опция | По умолчанию | Описание |
|---|---|---|
| `RootPath` | `Path.GetTempPath()` | Корневой каталог; относительные значения приводятся к полному пути до валидации. |
| `MaxAge` | 24 ч | Возраст, после которого подпапка считается просроченной (см. `AgeSource`). |
| `AgeSource` | `LastWriteTime` | `LastWriteTime` \| `CreationTime`. |
| `FolderPrefix` | `""` | Префикс имён создаваемых папок **и** фильтр очистки (простое имя — `.`/`..`, разделители и символы по [правилам путей](#правила-путей) запрещены). При `Naming = Date` ложится на первый сегмент датового пути (`up_` + `yyyy/MM/dd` → `up_2026/10/08`). |
| `FolderNameFormat` | `yyyy-MM-dd` | Формат даты/времени .NET, которым `Naming = Date` формирует имена папок — инвариантная культура, `TimeProvider` контейнера, локальное время. Работает с любым шаблоном (`yyyy-MM-dd/HH`, `yyyy/MM/dd`, `yyyyMMdd`, `yyyyMM/dd/HH` …); отрендеренная форма валидируется вместе с префиксом (сломанный формат, `..`, rooted-результат → `OptionsValidationException`). |
| `OverwriteFiles` | `true` | `SaveStreamAsync` / `CopyFileAsync` заменяют существующий целевой файл; `false` → запись падает с `IOException`, оригинал остаётся нетронутым. |
| `MaxFoldersPerPass` | 100 | Потолок удалений за один проход очистки. |
| `CleanupInterval` | 1 ч | Период фоновой очистки инстанса. |
| `VolumeScanInterval` | `0` | Отдельный период сканирования объёма; `0` — только перед проходом очистки. |
| `MinFreeSpace` | `0` | Минимум свободных байт, который должен остаться на томе корня; `0` — проверка выключена, том никогда не опрашивается. Положительное → один замер раз в `FreeSpaceCheckInterval`, вызывающий `OnFreeSpaceReached` edge-триггером. |
| `FreeSpaceCheckInterval` | 24 ч | Период проверки свободного места; первый замер при старте хоста. Должен быть положительным; учитывается только при `MinFreeSpace > 0`. |
| `ReadOnly` | `false` | См. [режим read-only](#режим-read-only). |
| `TrackVolume` | `false` | Измерять и кэшировать размеры папок вообще. |
| `MaxTotalSize` | `0` | Лимит объёма в байтах; `0` — выключен. Превышение порождает только событие. |
| `TouchDebounce` | 5 с | Период тишины перед тем, как запись обновит маркеры активности цепочки папок (собственной директории файла и всех предков до корня). |
| `Cleanup` | `AgeBased` | Встроенная стратегия очистки, переопределяется `UseCleanupStrategy<T>()`. |
| `Naming` | `GuidV7` | `GuidV7` \| `Date` (с `FolderNameFormat`), переопределяется `UseNamingStrategy<T>()`. |
| `OnVolumeExceeded` | `null` | Код-only edge-событие объёма; из конфигурации не биндится. |
| `OnFreeSpaceReached` | `null` | Код-only edge-событие свободного места; из конфигурации не биндится. |

Валидация — явная, через `IValidateOptions` (`ValidateOnStart()`), а не `ValidateDataAnnotations()`: последнее помечено `RequiresUnreferencedCode` (IL2026) и ломает Native AOT.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Путь разрешается вне корня (`..`, сосед с общим префиксом, абсолютный вне корня) | `SecurityException`. |
| `..`-сегмент или инъекционный символ в пути (`~`, `>`, shell-метасимволы, управляющие/невидимые Unicode) | `SecurityException` — отклоняется, даже если путь остался бы внутри корня. См. [правила путей](#правила-путей). |
| Абсолютный аргумент пути, остающийся внутри корня | Принимается наравне с относительным. |
| Мутация в read-only инстансе | `InvalidOperationException`. |
| Целевой файл существует, а `OverwriteFiles = false` | `IOException` из `SaveStreamAsync` / `CopyFileAsync` — оригинал остаётся нетронутым. |
| Невалидные опции | `OptionsValidationException` при первом резолве / старте хоста — никогда при регистрации (в том числе сломанный или инъекционный `FolderNameFormat`). |
| Неработающий корень на старте | `InvalidOperationException` из `CheckAccessAsync`, валит старт хоста. |
| Папка не удалилась после попыток | `LogWarning`, не засчитана, проход продолжается. |
| Проход очистки стартует, пока идёт запись | Проход отменяется до выборки — возвращает 0, повтор на следующем интервале. |
| Запись пришла посреди прохода очистки | Проход завершается отменой на следующем чекпоинте (возвращается частичный счётчик); запись продолжается после его разворота. |
| Касание маркеров папки ещё не приземлилось | Проход пропускает папку — только что записанный файл никогда не удаляется. |
| Стратегия бросила исключение или вернула путь наружу | Проход пропущен (исключение) или запись пропущена (путь наружу) с записью в лог — без падения. |
| Обработчик `OnVolumeExceeded` бросил | Перехвачено и залогировано; скан завершается. |
| Обработчик `OnFreeSpaceReached` бросил | Перехвачено и залогировано; проверка завершается. |
| Замер свободного места не удался (том пропал, нет прав) | Логируется циклом; повтор на следующем интервале — хост остаётся жив. |

## FilePathResolver

Компонент этого же пакета, пространство имён `Sa.Data.TempFolder.FilePathResolver`.

Резолвит нечёткие / неточные пути (как они хранятся в базе данных) в реальные пути файловой системы.
Каждый найденный маппинг кэшируется по пути из БД, поэтому повторный запрос — это чтение словаря
и один файловый пробник.

Публичный контур: `IFilePathResolver` (тип сервиса для DI), `FilePathResolver` (реализация по
умолчанию, включая флент-настройку) и `IFileSystemService` (шов к диску; дисковая
`DefaultFileSystemService` остаётся `internal`).

Каскад резолва (побеждает первое совпадение):

1. **Direct** — путь из БД существует в файловой системе буквально.
2. **Relative** — путь существует относительно `ConfiguredPath`.
3. **Incremental** — завершающие компоненты каталога из БД сопоставляются с
   каталогами под `ConfiguredPath`, от внутреннего к внешнему — поэтому потерянный
   ведущий префикс (`/storage/usbdisk1/mikopbx/astspool/monitor/2021/06/16/15/file.mp3` →
   `<root>/2021/06/16/15/file.mp3`) всё равно резолвится.
4. **Deep search** (по включению) — рекурсивный поиск по имени файла. Совпадения **не** кэшируются:
   файл, найденный где угодно в дереве, не несёт маппинга каталога.

| Метод | Описание |
|--------|-------------|
| `ResolvePath(string, bool asRelativePath = false)` | Резолвит путь из БД или возвращает `null`, если файл найти не удалось. Бросает `ArgumentException` при `null`/пробелах. |
| `WithPossibleExtensions(params string[])` | Расширения, перебираемые при нечётком поиске, если точное имя не найдено (`"mp3"` и `".mp3"` эквивалентны). |
| `WithDeepSearch(bool)` | Включает / выключает рекурсивный поиск по имени файла. |
| `WithForceSearch(bool)` | Если включён, каждый вызов заново прогоняет весь каскад вместо чтения пофайлового кэша. |
| `WithMap(string)` | Явный глобальный маппинг, применяемый до каскада: пути из БД, начинающиеся с `map`, ищутся напрямую под `ConfiguredPath`. |
| `IsResolved` / `IsDeepSearch` / `IsForceSearchEnabled` | Текущее состояние резолвера. |
| `Resolved` (событие) | Срабатывает один раз — при установке первого маппинга. |

```csharp
var resolver = FilePathResolver.Create("/records")
    .WithPossibleExtensions("mp3", "wav")
    .WithDeepSearch(true);

// "/storage/usbdisk1/mikopbx/astspool/monitor/2021/06/16/15/has-root.mp3"
//   → /records/2021/06/16/15/has-root.mp3  (совпадение по суффиксу каталога)
string? full = resolver.ResolvePath(dbPath);
string? rel  = resolver.ResolvePath(dbPath, asRelativePath: true); // "2021/06/16/15/has-root.mp3"
```

### Регистрация (keyed, как `AddSaTempFolder`)

| Вызов | Описание |
|------|-------------|
| `services.AddFilePathResolver(name, configuredPath, configure?)` | Регистрирует `IFilePathResolver` под ключом `name` — один хост может обслуживать несколько именованных корней. |
| `services.AddFilePathResolver(configuredPath, configure?)` | То же под ключом по умолчанию `Setup.DefaultName` (`"default"`, класс `Setup` резолвера в `Sa.Data.TempFolder.FilePathResolver`). |
| `sp.GetRequiredKeyedService<IFilePathResolver>(name)` | Резолвит инстанс — обычный `GetRequiredService<IFilePathResolver>()` keyed-сервисы не находит. |

- Имена регистрации должны быть уникальны: дубликат бросает `InvalidOperationException` при
  регистрации; `null`/пробелы в `name` или `configuredPath` → `ArgumentException`.
- Регистрация ленивая: отсутствующий корень проявится как `DirectoryNotFoundException` при
  первом резолве — но не при регистрации.
- `configure` выполняется один раз, при построении инстанса, и — та же флент-цепочка, что и
  при прямой сборке: `r => r.WithMap(...).WithPossibleExtensions(...).WithDeepSearch(true)`.
- Шов к диску: сначала keyed `IFileSystemService` (на конкретную регистрацию), затем обычный,
  иначе — дисковая реализация по умолчанию.

```csharp
builder.Services.AddFilePathResolver("records", "/data/records",
    r => r.WithPossibleExtensions("mp3", "wav").WithDeepSearch(true));

// где-то дальше:
var resolver = sp.GetRequiredKeyedService<IFilePathResolver>("records");
string? full = resolver.ResolvePath(dbPath);
string? rel  = resolver.ResolvePath(dbPath, asRelativePath: true);
```
