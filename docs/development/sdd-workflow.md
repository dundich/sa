# SDD workflow

## Жизненный цикл изменения
`Idea → Spec → Review → Plan → Tasks → Implement → Verify → Close`

### 1. Spec
Определяет **что** должно происходить и почему, а не конкретную реализацию. Обязательные части:
- контекст и проблема;
- цели и не-цели;
- пользовательские/системные сценарии;
- требования и ограничения;
- критерии приёмки, включая ошибки и отмену;
- совместимость, производительность, безопасность и observability, когда применимо;
- открытые вопросы.

### 2. Review
Не начинать реализацию при нерешённых вопросах, которые влияют на API, совместимость, данные или acceptance criteria. Зафиксировать решение в spec/ADR.

### 3. Plan
Определяет затрагиваемые проекты и файлы, архитектурный подход, миграцию, тестирование, риски и откат. Не подменяет spec.

### 4. Tasks
Небольшие шаги с проверяемым результатом. Каждая задача должна указывать тест/проверку и зависимость от других задач.

### 5. Implement
Следовать плану. Если обнаружено противоречие — остановиться, обновить spec/plan и согласовать изменение, а не молча менять требования.

### 6. Verify
Проверить каждый acceptance criterion и тестовые уровни, относящиеся к изменению. Не объявлять завершённым только потому, что компиляция прошла.

## Обязательные правила для Sa
- Публичные API, NuGet IDs, target frameworks и packing metadata не меняются случайно.
- Native AOT/trimming, nullable и analyzer constraints проверяются для затрагиваемых библиотек.
- PostgreSQL/Minio/Testcontainers нужны там, где изменяется соответствующая интеграция.
- Изменения путей проверяются отдельно от функциональных изменений.
- Спецификация — источник требований; README и API docs объясняют использование.
- Отсутствие теста допустимо только с явным обоснованием в plan.

## Definition of Ready
Spec имеет однозначные сценарии и проверяемые acceptance criteria; зависимости/ограничения известны; спорные вопросы решены.

## Definition of Done
Все acceptance criteria выполнены; релевантные тесты и сборки пройдены; документация обновлена; API/пакеты проверены; spec/plan отражают фактический результат.
