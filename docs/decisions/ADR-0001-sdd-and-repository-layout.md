# ADR-0001: SDD и стратегия организации репозитория

- Статус: Proposed
- Дата: 2026-10-30

## Контекст
Sa содержит набор .NET-библиотек, samples и тестовых проектов. Для управляемых изменений требуется отделить требования от реализации. Реорганизация каталогов может затронуть ссылки проектов, сборку, упаковку и CI.

## Решение
1. Ввести `specs/` как нормативный источник требований и acceptance criteria.
2. Хранить шаблоны отдельно в `templates/`.
3. Хранить архитектурные/справочные материалы в `docs/`.
4. Сначала внедрить SDD без перемещения production-кода.
5. Считать `src/Libraries/` необязательной целью: принять её только после инвентаризации зависимостей и отдельного review.
6. Любое перемещение проектов выполнять отдельным небольшим PR с полным build/test/package.

## Последствия
Плюсы: требования проверяемы, реорганизация безопаснее, решения прослеживаемы.
Минусы: дополнительная документация и review; нужен процесс поддержания specs в актуальном состоянии.

## Альтернативы
- Переместить все каталоги одним PR: отклонено из-за высокого радиуса регрессии.
- Хранить спеки в `docs/`: отклонено, поскольку смешивает нормативные требования и объяснительные документы.
- Немедленно внедрить жёсткие слои Domain/Application/Infrastructure: отклонено, поскольку границы репозитория соответствуют отдельным библиотекам, а не одному приложению.
